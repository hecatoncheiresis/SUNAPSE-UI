# Reasoning Canvas

[English version](README.en.md)

Локальное веб-приложение с node-холстом (в духе ComfyUI) для длинных рассуждений с LLM. Каждый **Chat Node** — это диалог «вопрос–ответ» с моделью, сохранённый в обычный Markdown-файл. **Lens Node** сжимает один или несколько таких диалогов в компактный **Digest**, который затем подаётся на вход новым Chat Node. Так можно ветвить рассуждения и переносить из одного диалога в другой только суть.

Все данные — простые `.md`-файлы в папке проекта: их можно читать без приложения, хранить в git, копировать и переносить.

## Возможности

- **Chat Node** — диалог с LLM; каждый вопрос и ответ сразу дописывается в Dialogue File. Модель можно менять в любой момент чата. Ответы приходят потоком (streaming), вопросы и ответы отображаются как Markdown; при появлении ответа чат не прокручивается сам.
- **System Prompt** — текст, привязанный к Chat Node (шестерёнка ⚙ между Fork и корзиной; она зелёная, пока текст не пуст). Подставляется перед каждым вопросом в запросе к LLM, но не показывается в истории и не входит в вопрос; можно менять в любой момент, действует на следующие вопросы и учитывается Token Meter.
- **Lens Node** двух видов:
  - **Exact Lens Node** — вы сами заполняете четыре раздела «Context Handoff Questionnaire»;
  - **Auto Lens Node** — разделы заполняет **Extraction** (отдельная модель с настраиваемым Extraction Prompt), после чего их можно править вручную.
- **Digest** — результат Run: сжатый контекст заданного размера (**Compression Target** — процент от входа или явное число токенов, передаётся модели как мягкая цель). Digest показывается как Markdown; клик переключает его в текстовый режим для правки прямо в узле (изменения сохраняются автоматически).
- **Token Meter** — вертикальный «стакан» с градиентом зелёный→красный: показывает, насколько заполнен контекст относительно **Context Limit** модели. Использует реальные данные `usage` из ответа API, а до отправки — оценку. Лимит никогда не блокирует запрос.
- **Edge State** — цвет связи показывает, согласованы ли узлы: белый — ещё не использовано, зелёный — согласовано, красный — после этого что-то изменилось (только сигнал, ничего не перезапускается автоматически).
- **Node Defaults** — шестерёнка ⚙ после каждого типа узла в Node Search задаёт, с чем стартуют все *новые* узлы этого типа в проекте: у Chat Node это модель и System Prompt; у Exact Lens Node — модель и Compression Target; у Auto Lens Node — модель для Run, Extraction Model, Extraction Prompt и Compression Target. Изменения сохраняются сразу.
- **Fork** — новый Chat Node с копией вопросов, ответов и System Prompt в поле ввода (можно отредактировать и выбрать другую модель).
- **Remove / Restore** — удаление узла с холста (корзина в узле или клавиша `Delete`) не удаляет его файл. Узел возвращается вместе со связями, записанными в файле: через `Ctrl+Z` сразу после удаления или через API (`GET /restorable`, `POST /restorable/:id/restore`); отдельного меню Restore в интерфейсе нет.
- **Undo / Redo** — `Ctrl+Z`, `Ctrl+Shift+Z` / `Ctrl+Y` для раскладки и структуры холста.
- **Цвета пинов**: входной пин окрашивается в цвет своей связи (белый, зелёный, красный); без связей он белый. Палитра интерфейса — нейтрально-серый холст, узлы и панели с синим акцентом и зелёными связями.
- **Любая OpenAI-совместимая модель**: OpenAI, OpenRouter, Gemini (через OpenAI-совместимый endpoint), Ollama, LM Studio и т. д.
- **Настройка интерфейса** (Display Settings): поля окна, шрифт, масштаб интерфейса 70–500 %.

## Быстрый старт

### Требования

- Node.js (современная LTS-версия) и npm.

### Установка и запуск

```bash
npm install
npm run build      # собрать фронтенд (vite build → dist/)
npm start          # запустить сервер
```

Откройте <http://127.0.0.1:3100>. Порт меняется переменной `PORT`:

```bash
PORT=4000 npm start
```

Сервер слушает только `127.0.0.1` — приложение рассчитано на локальное использование, без аккаунтов и хостинга.

### Режим разработки

В двух терминалах:

```bash
npm run dev:server   # сервер с автоперезапуском (tsx watch)
npm run dev:web      # Vite dev-сервер для фронтенда (проксирует /api/ на 127.0.0.1:3100)
```

### Первые шаги в приложении

1. Откройте **Sidebar** (левая панель) → **Models** (Model Panel, откроется во вкладке браузера) и добавьте модель: base URL, API key, имя модели, Context Limit.
2. В Sidebar выберите или создайте **Project** — папку на диске (есть встроенный браузер папок и список недавних проектов).
3. Правый клик по пустому месту холста → **Canvas Menu** → «Create node» → **Node Search** → создайте Chat Node: выбранный тип «повиснет» на курсоре, левый клик ставит узел на место, `Esc` или правый клик отменяют. (Шестерёнка ⚙ рядом с типом узла открывает [Node Defaults](#node-defaults) — модель и прочие настройки для будущих узлов этого типа.)
4. Задайте вопрос. Создайте Lens Node, протяните связь от Chat Node к Lens Node, нажмите **Run** — получится Digest.
5. Создайте новый Chat Node и протяните связь от Lens Node к нему: Digest уйдёт моделью вместе с первым вопросом.

## Как это работает

### Граф: Chat → Lens → Chat

| Связь | Разрешена | Условие |
|---|---|---|
| Chat Node → Lens Node | да | в любой момент; связь, добавленная после Run, остаётся белой и её можно удалить |
| Lens Node → Chat Node | да | у Lens Node должен быть Digest; и только до первого вопроса в Chat Node |
| Chat → Chat | **нет** | — |
| Lens → Lens | **нет** | — |

Входы и выходы не ограничены: один Lens Node может читать несколько чатов, один выход — питать много узлов. Связь, которая уже «передала информацию» (Lens → Chat после первого вопроса, Chat → Lens, чей чат учтён в Run), удалить нельзя — она показывает, откуда пришла информация. Остальные связи удаляются выделением и клавишей `Delete` (с возможностью Undo).

### Chat Node

- System Prompt (см. [Возможности](#возможности)) записывается в Dialogue File служебной информацией перед каждым вопросом и в заголовке, поэтому Restore его возвращает.
- Единственный вход — Digest'ы от Lens Node. Слоты входа (**Input Slot**) появляются по одному: заполнили — ниже появился новый; первый вопрос их закрывает.
- Digest'ы попадают в контекст **один раз, с первым вопросом**, и записываются в Dialogue File как часть истории (см. [ADR-0002](docs/adr/0002-digest-recorded-in-chat-and-no-lock.md)); дальше заново не подгружаются.
- Технический заголовок файла и служебная информация никогда не отправляются в LLM — только вопросы, ответы и Digest'ы.
- Ошибка вызова LLM показывается пользователю, не записывается в файл как ответ, а набранный вопрос не теряется.

### Lens Node

- На вход получает диалоги (только вопросы и ответы) всех подключённых Chat Node одним блоком под заголовками `### nodeN`, плюс Handoff Questionnaire и Compression Target.
- **Run** — явное действие; ни одна операция не запускается автоматически. Повторный Run перезаписывает единственный Digest (истории версий нет).
- Run блокируют только структурные ошибки (нет входов / модели), но не размер контекста.
- **Auto Lens Node** дополнительно имеет **Extraction**: диалоги + Extraction Prompt отправляются в Extraction Model, ответ раскладывается по четырём разделам (перезаписывая их целиком). У такого узла два Token Meter: слева — для Extraction Model, справа — для самого Lens Node. У Exact Lens Node Token Meter один (слева, считает то, что уходит на вход), а правый край показывает размер Digest в токенах (ожидаемый по Compression Target до Run, реальный после).

Кнопка удаления узла (корзина) у Lens Node, как и у Chat Node, стоит в верхней строке узла; удаление спрашивает подтверждение, файл узла сохраняется.

Четыре раздела Handoff Questionnaire: *Project Scope & Objective*, *Established Rules & Constraints*, *Discarded Ideas & Solved Blockers*, *Current Artifacts & State*.

### Node Defaults

Шестерёнка ⚙ после каждого типа в Node Search открывает настройки по умолчанию для этого типа; клик по самому названию по-прежнему создаёт узел.

| Тип | Что настраивается |
|---|---|
| Chat Node | модель, System Prompt |
| Exact Lens Node | модель, Compression Target (процент или токены) |
| Auto Lens Node | модель для Run, Extraction Model, Extraction Prompt, Compression Target |

- Окно настроек сохраняет изменения сразу (кнопки «Save» нет); `Esc` или «← Back» возвращает в Node Search; «Restore built-in values» сбрасывает настройки на встроенные.
- Настройки относятся к **проекту** (хранятся в `canvas.json`, отдельно для каждого типа), не к браузеру и не к программе; `Undo` их не откатывает.
- Действуют только на узлы, созданные через Node Search после изменения. Уже существующие узлы, Fork и Restore берут значения из исходного узла или файла.
- Extraction Prompt из настроек становится стартовым текстом новых Auto Lens Node, и именно к нему возвращает кнопка «Reset prompt» в узле; пока он не задан, действует встроенный текст.
- Незаданная настройка или удалённая модель просто оставляют поле пустым в новом узле, без ошибки.

### Edge State

- **Chat → Lens**: белый — Lens Node ещё не запускали; зелёный — Run использовал чат в его нынешнем виде; красный — в чат что-то добавилось после Run.
- **Lens → Chat**: белый — первый вопрос ещё не забрал Digest; зелёный — Digest, записанный в чате, совпадает с текущим; красный — они различаются.

## Работа с холстом

- **Создание узла**: правый клик по пустому месту → Canvas Menu → Node Search; выбранный узел висит на курсоре (за левый верхний угол), пока левый клик не поставит его; шестерёнка ⚙ рядом с типом открывает Node Defaults.
- **Standard Size**: у всех узлов один размер, пропорциональный окну браузера (за вычетом четырёх Window Margin). Вручную размер не меняется; кнопка в Sidebar применяет текущий размер ко всем узлам сразу ([ADR-0003](docs/adr/0003-one-node-size-and-zoom-floor-at-focus.md)).
- **Focus**: двойной клик по узлу — вид центрируется на нём, масштаб становится **Focus Zoom**, курсор уходит в первое поле для ввода.
- **Focus Zoom**: максимальный масштаб холста; именно в нём узлы «рабочие». При меньшем масштабе узлы инертны: их можно двигать, соединять и фокусировать. Отдалять можно до 1/10 Focus Zoom.
- **Sidebar** (сворачивается; состояние запоминается в браузере): сменить проект, Models (Model Panel), Display Settings, «Standard Size для всех узлов».
- **Display Settings**: поля окна (0–40 % с каждой стороны), шрифт, Interface Scale (70–500 %). Хранятся в браузере, не в проекте.

## Формат проекта на диске

Project — это папка с `canvas.json` и файлами узлов:

```
my-project/
├── canvas.json        # раскладка, связи и Node Defaults (главный источник истины для живого графа)
├── chats/             # Dialogue Files Chat Node: node1.md, node3.md, …
├── exact-lenses/      # Digest'ы Exact Lens Node
└── auto-lenses/       # Digest'ы Auto Lens Node
```

- Все узлы называются `nodeN` по единому сквозному счётчику; номера **никогда не переиспользуются**, даже после удаления узла.
- Файл узла начинается с технического заголовка (модель, время создания, связи и т. д.), затем идёт содержимое: для чата — чередующиеся блоки `## Question` / `## Answer` (файлы старых версий с `## Вопрос` / `## Ответ` по-прежнему читаются), для Lens Node — разделы Handoff Questionnaire и `## Digest`.
- Пока узел на холсте, `canvas.json` главнее связей, записанных в файле узла. При расхождении при загрузке показывается предупреждение.
- Каждое изменение записывается немедленно (write-through), поэтому закрытие браузера ничего не теряет.
- Форматы файлов инкапсулированы в `src/server/nodeFile.ts`.

## Модели и безопасность ключей

- Модели принадлежат **программе**, а не проекту: они хранятся в `models.json` в корне репозитория и доступны во всех проектах. Список недавних проектов — в `recent-projects.json`.
- Оба файла перечислены в `.gitignore`, поэтому ключи не попадают в git вместе с диалогами. Директорию можно переопределить переменной `RC_CONFIG_DIR`.
- Браузер **никогда не получает API-ключи**: HTTP API отдаёт только «безключевое» представление моделей.
- Поддерживается только OpenAI-совместимый Chat Completions API (нативные API Anthropic и Gemini не используются).

Формат записи модели:

```json
{
  "models": [
    {
      "id": "model1",
      "baseUrl": "https://generativelanguage.googleapis.com/v1beta/openai/",
      "apiKey": "…",
      "modelName": "gemini-3.5-flash-lite",
      "contextLimit": 128000
    }
  ]
}
```

Обычно этот файл создаётся через Model Panel, редактировать вручную не нужно.

## Архитектура

Локальный сервер на Node.js + TypeScript (Fastify) и React-фронтенд на React Flow (`@xyflow/react`). Базы данных нет — хранилище это Markdown-файлы.

```
src/
├── server/
│   ├── main.ts           # точка входа, порт, каталог конфигурации
│   ├── app.ts            # Fastify-приложение и все HTTP-маршруты
│   ├── projectStore.ts   # открытие проекта, canvas.json, выдача имён nodeN
│   ├── nodeFile.ts       # парсинг и сериализация .md-форматов
│   ├── graphRules.ts     # чистые правила связей
│   ├── graphService.ts   # создание/удаление узлов и связей, Fork
│   ├── nodeDefaults.ts   # Node Defaults: чтение, запись, применение к новому узлу
│   ├── chatNode.ts       # вопросы, ответы, streaming, Token Meter чата
│   ├── lensNode.ts       # настройки, Run, Extraction, Token Meter Lens Node
│   ├── extraction.ts     # промпт и разбор Extraction
│   ├── edgeState.ts      # цвета связей
│   ├── restore.ts        # Restore и предупреждения о расхождениях
│   ├── modelStore.ts     # реестр моделей (ключи только на сервере)
│   ├── llmClient.ts      # клиент OpenAI-совместимого API
│   ├── tokens.ts         # оценка токенов и учёт usage
│   ├── recentProjects.ts # список недавних проектов
│   └── fileLock.ts, errors.ts
└── web/
    ├── Markdown.tsx, SystemPromptButton.tsx, pinStates.ts
    ├── CanvasView.tsx, ChatNodeView.tsx, LensNodeView.tsx, NodeShell.tsx, PinEdge.tsx, RemoveNodeButton.tsx
    ├── ModelPanel.tsx, DisplaySettingsPanel.tsx, Sidebar.tsx, NodeSearch.tsx, NodeDefaultsPanel.tsx, FolderPicker.tsx
    ├── TokenMeter.tsx, api.ts, history.ts (Undo), canvasActions.ts, graphEvents.ts, displaySettings.ts, nodeSize.ts
    └── style.css
tests/   # Vitest: тесты через HTTP API
e2e/     # Playwright: сценарии в реальном UI
```

Принципы:

- **Файлы узлов первичны** ([ADR-0001](docs/adr/0001-node-files-are-primary.md)): удаление с холста не удаляет файл.
- **Глубокие модули** за небольшими интерфейсами; единый шов для тестов — HTTP API сервера.
- Словарь предметной области зафиксирован в [`GLOSSARY.md`](GLOSSARY.md) и используется дословно в коде и UI.

## HTTP API

Основные маршруты (все под `/api`):

| Область | Маршруты |
|---|---|
| Проект | `POST /project/open`, `GET /projects/recent`, `GET /canvas`, `GET /fs/list` |
| Node Defaults | `GET/PUT /node-defaults/:type` (`chat`, `exact-lens`, `auto-lens`) |
| Узлы | `POST /nodes`, `PUT /nodes/:id/position`, `PUT /nodes/:id/size`, `DELETE /nodes/:id`, `POST /nodes/:id/fork` |
| Связи | `POST /edges`, `DELETE /edges/:id`, `GET /edges/states` |
| Restore | `GET /restorable`, `POST /restorable/:id/restore`, `GET /warnings` |
| Chat Node | `GET /nodes/:id/chat`, `PUT /nodes/:id/model`, `PUT /nodes/:id/system-prompt`, `POST /nodes/:id/tokens`, `POST /nodes/:id/messages`, `POST /nodes/:id/messages/stream` |
| Lens Node | `GET/PUT /nodes/:id/lens`, `PUT /nodes/:id/digest`, `GET /nodes/:id/lens/tokens`, `GET /nodes/:id/lens/extraction-tokens`, `POST /nodes/:id/extract`, `POST /nodes/:id/run` |
| Модели | `GET/POST /models`, `GET/PUT/DELETE /models/:id` |

## Разработка и тесты

| Команда | Что делает |
|---|---|
| `npm run check` | главный гейт: проверка глоссария → `tsc --noEmit` → `vite build` → `vitest run` |
| `npm test` | только Vitest |
| `npm run typecheck` | только проверка типов |
| `npm run check:ui` | сборка + Playwright-сценарии в реальном браузере |

- Хук `pre-commit` (`.githooks/`) запускает `npm run check`; он подключается автоматически через `npm install` (скрипт `prepare`).
- Тесты серверной части работают через HTTP API с временной папкой проекта и поддельным OpenAI-совместимым сервером (`tests/helpers/fakeLlm.ts`), который возвращает заготовленные ответы и записывает все запросы. Проверяются внешние эффекты: ответ, файлы на диске, точные сообщения, полученные «моделью».
- `scripts/check-glossary.mjs` ловит запрещённые синонимы (строки `_Avoid_` в глоссарии).
- Для `check:ui` один раз на машине нужен Chromium: `npx playwright install chromium` (на Linux также `sudo npx playwright install-deps chromium`).
